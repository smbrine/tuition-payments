# Учебный модуль учета оплаты обучения

Программа для кейс-задачи № 3 производственной (эксплуатационной) практики: разработка ПО для финансовых технологий, адаптированная к учету оплаты обучения в университете.
Стенд на Python и SQLite с веб-интерфейсом на HTML, CSS и JavaScript. Все демонстрационные записи вымышлены.

## Запуск

Нужен Python 3.10 или новее. Внешние библиотеки не требуются.

```sh
python3 app.py --demo
```

Откройте http://127.0.0.1:8080. Остановка: Ctrl+C. При повторном запуске база tuition.db сохраняется, демонстрационные записи не дублируются. Другой порт: `--port 8081`.

В демонстрационном наборе начислено 105000 руб., оплачено 20000 руб., остаток 85000 руб. Статус просрочки зависит от текущей даты компьютера.

## Возможности

- Создание начисления по коду студента и уникальному договору.
- Регистрация частичной или полной оплаты с уникальным номером платежа.
- Расчет остатка и статуса; поиск в реестре; выгрузка CSV.
- Контроль сумм, дат, повторных платежей и превышения остатка.

Для простоты прототип использует одно начисление на один договор. Реестр показывает текущее состояние, а не исторический срез.
Просрочка означает положительный остаток после указанного срока оплаты. Суммы хранятся в целых копейках.

## Проверки

```sh
python3 -m unittest -v
```

Автоматизированные проверки охватывают частичную/полную оплату, уникальность платежей и договоров, переплату, суммы и даты, экспорт/восстановление копии, защиту текстовых полей CSV и HTTP-сценарии. GitHub Actions выполняет их при push и pull request.

## Резервная копия

Остановите сервер. Выполните `python3 app.py --backup backup.db`. Для проверки копии запустите `python3 app.py --db backup.db --port 8081`.

Для восстановления используйте копию как рабочую базу: `python3 app.py --db backup.db`. Сохраняйте исходную копию отдельно. Базы данных исключены из Git через `.gitignore`.

## Структура и документация

- `app.py` — расчеты, SQLite, HTTP API и команды запуска.
- `index.html`, `app.js`, `style.css` — браузерный интерфейс.
- `test_app.py` — модульные и HTTP-тесты.
- [Описание кейса № 3](docs/case-3.md) — требования, проектирование, проверка, локальное внедрение и сопровождение.

API: `GET /api/charges`, `POST /api/charges`, `POST /api/payments`, `GET /export.csv`. Суммы во входных запросах задаются в рублях (предпочтительно строкой, например `"1000.50"`), в JSON реестра — целыми копейками. POST-запросы требуют заголовок `Origin`, совпадающий с адресом локального сервера.

## Публикация на GitHub

Создайте пустой репозиторий `tuition-payments` в своем аккаунте GitHub. Из папки проекта выполните команды, заменив `YOUR_USERNAME` своим логином:

```sh
git remote add origin https://github.com/YOUR_USERNAME/tuition-payments.git
git push -u origin main
```

Исходники готовы к публикации; для проверки преподаватель может клонировать репозиторий и выполнить команды запуска выше. GitHub Pages не запускает Python-сервер — приложение нужно запускать локально.

## Границы применения

Только локальный однопользовательский учебный стенд с вымышленными кодами студентов. Авторизация и роли не реализованы. Не размещайте сервис в сети и не загружайте реальные персональные или банковские данные. Стенд не принимает деньги, не проводит банковские операции, не формирует фискальные чеки и не подключен к системам университета. Перед возможным промышленным использованием нужны отдельная проверка требований, авторизация, аудит, защита выгрузок, резервирование и интеграционное тестирование.
