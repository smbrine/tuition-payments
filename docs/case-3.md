# Кейс-задача № 3: учет оплаты обучения

Учебная адаптация задания по разработке финансового ПО к деятельности университета.
Программа учитывает начисления и зарегистрированные оплаты; прием денежных средств и банковские интеграции в объем проекта не входят.

## Анализ требований

Пользователь — сотрудник, ведущий учет оплаты обучения. Он создает начисление по коду студента и договору, указывает сумму и срок, затем регистрирует поступившие платежи. Реестр показывает начисленную и оплаченную сумму, остаток и статус. Есть поиск и экспорт CSV.

Правила: один договор — одно начисление; одному начислению соответствует несколько платежей. Положительная сумма содержит не более двух десятичных знаков. Переплата запрещена. Договор и номер платежа уникальны. Срок считается просроченным со следующего дня при положительном остатке. Реестр отражает текущее состояние, включая все введенные платежи; исторический срез не реализован.

Нефункциональные требования: локальная работа без сторонних зависимостей, сохранение между запусками, атомарная регистрация платежа, точный расчет в целых копейках и возможность резервного копирования.

## Проектирование

Браузерный интерфейс HTML/CSS/JavaScript обращается к HTTP-серверу Python. Сервер проверяет данные и использует SQLite через параметризованные SQL-запросы.

`charges`: ID, код студента, уникальный договор, сумма в копейках, срок оплаты.
`payments`: ID, внешний ключ начисления, сумма в копейках, дата, уникальный номер платежа.
Остаток вычисляется как сумма начисления минус сумма связанных платежей.

## Разработка и проверка

`app.py` содержит класс Ledger, HTTP API и команды запуска/копирования. `index.html`, `app.js` и `style.css` содержат интерфейс. `test_app.py` проверяет расчеты, повторные операции, переплату, даты, некорректный ввод, экспорт, восстановление и HTTP-запросы. GitHub Actions запускает тесты при push и pull request. Команда локального запуска тестов: `python3 -m unittest -v`.

Ручной приемочный сценарий:

1. Запустить `python3 app.py --demo` и открыть локальный адрес.
2. Убедиться, что начислено 105000 руб., оплачено 20000 руб., остаток 85000 руб.
3. Создать начисление ST-003 / EDU-2026-003 на 1000 руб.
4. По его ID зарегистрировать платеж 400 руб. с уникальным номером; остаток должен составить 600 руб.
5. Повторить номер платежа и попытаться оплатить 600.01 руб.; обе операции должны отклоняться.
6. Оплатить 600 руб. с новым номером; статус должен стать «Оплачено».
7. Проверить поиск, CSV и сохранение данных после перезапуска.

## Локальное внедрение и сопровождение

Требуется Python 3.10+ и браузер. Инструкции запуска, копирования и восстановления находятся в README. Для обновления следует остановить процесс, создать резервную копию, заменить исходники, выполнить тесты и запустить приложение. При изменении схемы БД понадобится отдельная миграция; текущая версия ее не реализует.

## Ограничения и дальнейшее развитие

Это однопользовательский учебный прототип с вымышленными данными. Он не проходил промышленное внедрение, нагрузочные испытания или проверку соответствия требованиям к обработке реальных финансовых и персональных данных. Авторизация и журнал действий отсутствуют.

Следующие шаги: роли и доступ, аудит изменений, графики начислений, корректировки платежей, автоматическое резервирование, затем многопользовательский сервер и интеграции. Эти возможности требуют отдельной реализации и проверки.
